## 2026-09-05 VSCodeでwebのブレークポイントが止まらない場合の切り分け

`apps/api` では止まるのに `apps/web` だけブレークポイントが中抜きのまま反応しない場合、疑う順番は次のとおり。

1. **前回のサーバーが残っていないか。** `next dev` は 1 プロジェクト 1 起動しか許さず、古いプロセスが port を握ったままだと、新しいデバッグセッションは別の空きポート（3001, 3002 …）で起動し、ブラウザで開いている `localhost:3000` は古い（デバッガに繋がっていない）サーバーのままになる。**これが原因のほとんど**。

   ```powershell
   Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
     Where-Object { 3000,3001,3002,3003 -contains $_.LocalPort } |
     Select-Object LocalPort, OwningProcess
   ```

   本来動いているはずのポート以外に `node` プロセスが残っていたら、プロセス名を確認してから止める。

   ```powershell
   Get-Process -Id <OwningProcess> | Select-Object Id, ProcessName   # node であることを確認
   Stop-Process -Id <OwningProcess> -Force
   ```

   **ブラウザのタブを閉じただけではサーバーは止まらない。** 実行とデバッグの■（停止）か `Shift+F5` で明示的に止める。

2. **`launch.json` の `type` が `node-terminal` になっているか。** `"type": "node", "runtimeExecutable": "pnpm"` だと、Windows では `pnpm` が `.cmd` 経由になり、そこから生まれる `next dev` の子プロセスまで自動アタッチできないことがある。`type: "node-terminal"` + `"command": "pnpm run dev"` にすると解消する。

3. **それでも止まらなければ Turbopack を疑う。** `apps/web/package.json` に `"dev:debug": "next dev --webpack"` を用意してある。Turbopack はデフォルトのビルダーで高速だが、ソースマップの対応づけで VS Code のデバッガと相性が悪いことがある。`dev:debug` で起動して切り分ける（普段の `pnpm dev:web` は Turbopack のままでよい）。

## 2026-09-05 依存パッケージをどこへ入れるか

アプリで使うものは各アプリへ、両方で使う開発ツールだけをルートへ入れる。ルートへ入れるときは `-w` が要る。

```powershell
pnpm --filter web add next react react-dom      # 画面側だけで使う
pnpm --filter api add -D @types/node            # API側だけで使う
pnpm add -D -w typescript@~6.0.3                # 両方で使う開発ツール
```

`-w` を付けずにルートで `pnpm add` するとエラーになる。「ここは束ね役のルートだが本当にここへ入れるのか」という確認のため。

## 2026-09-05 ルートに入れた型定義は各アプリから見えない

ルートの `package.json` に `@types/node` があっても、`apps/api` からは参照できず次のエラーになる。

```
error TS2591: Cannot find name 'process'. Do you need to install type definitions for node?
```

各パッケージは自分の依存だけを参照するため。ルートで共有されるのは `tsc` や `eslint` のような**コマンド**であって、型定義ではない。使うパッケージへ個別に入れる。

```powershell
pnpm --filter api add -D @types/node@^22.10.5
```

バージョンはルートと揃える（実行する Node のバージョンとずれないようにするため）。

## 2026-09-05 TypeScript6では@typesの自動読み込みが効かない

`apps/api/node_modules/@types/node` が実在していても、上と同じ `TS2591` が消えないことがある。TypeScript 6 で `@types` の自動読み込みが厳格化されたため、`tsconfig.json` で明示する。

```json
{
  "compilerOptions": {
    "types": ["node"]
  }
}
```

## 2026-09-05 TypeScript6ではoutDirにrootDirの明示が要る

`nest build` が次のエラーで止まる。

```
error TS5011: The common source directory of 'tsconfig.json' is './src'.
The 'rootDir' setting must be explicitly set to this or another path to adjust your output's file layout.
```

TypeScript 6 の新しい要求。`outDir` を使うなら `rootDir` を書く。書かないと出力先が `dist/src/main.js` のようにひとつ深くなり、`package.json` の `"start": "node dist/main.js"` と合わなくなる。

```json
{
  "compilerOptions": {
    "rootDir": "./src",
    "outDir": "./dist"
  }
}
```

## 2026-09-05 pnpm addで指定したチルダが山記号へ書き換わる

`~6.0.3`（6.0 系に固定）と指定しても、`package.json` には `^6.0.3`（6 系なら何でも可）と記録される。pnpm の既定の記号が `^` のため。**指定した記号が保たれるとは限らないので、実行後に `package.json` を目で確認する。**

TypeScript は `typescript-eslint` が `<6.1.0` までしか対応しておらず、`^` のままだと将来 6.1 へ上がって `pnpm lint` が動かなくなる。手で `~6.0.3` へ直す。

## 2026-09-05 自動生成されるファイルをPrettierの対象から外す

`apps/web/next-env.d.ts` は Next.js が起動のたびに作り直す。Prettier で整形すると次のビルドで元へ戻り、`pnpm format:check` が失敗する。[`.prettierignore`](../../../.prettierignore) へ次を入れてある。

```
apps/web/.next/
apps/web/next-env.d.ts
apps/api/dist/
```

## 2026-09-05 pnpm addの直後は実体が入っていないことがある

`pnpm --filter <名前> add` の出力に次が出た場合、`pnpm-lock.yaml` は更新されたが `node_modules` の実体はまだ入っていない。

```
WARN `node_modules` is present. Lockfile only installation will make it out-of-date
```

`added 0, downloaded 0` と表示されるのが目印。続けて `pnpm install` を打つと揃う。

```powershell
pnpm install
```

## 2026-09-05 Nextjs16はmiddlewareではなくproxyという名前でexportする

`apps/web/AGENTS.md`に書いたとおり `src/proxy.ts` というファイル名は正しいが、そこから**`export function middleware(...)`という名前でexportすると起動時にエラーになる**。

```
⨯ The file "./src\proxy.ts" must export a function, either as a default export or as a named "proxy" export.
```

Next.js 16では、ファイル名だけでなくexportする関数名も`middleware`から`proxy`へ変わっている。`export function proxy(...)`にする。

## 2026-09-05 next devがAGENTSmdへ自動で追記する機能を止める

`next dev`を起動するたびに、`apps/web/AGENTS.md`の末尾へ次のような注意書きが自動で追記される。

```
<!-- BEGIN:nextjs-agent-rules -->
...
<!-- END:nextjs-agent-rules -->
```

このリポジトリの`AGENTS.md`はClaude/Codex/Copilot共通の正本であり、Next.js側に書き換えさせたくない。`next.config.ts`で無効化する。

```ts
const nextConfig: NextConfig = {
  agentRules: false,
  // ...
};
```

もし追記されてしまったら、コミット前に取り消す。

```powershell
git checkout -- apps/web/AGENTS.md
```
