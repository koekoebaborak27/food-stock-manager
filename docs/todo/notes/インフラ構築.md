# インフラ構築（GCP / gcloud CLI）の落とし穴

## 2026-09-06 Windows + Git Bashから`gcloud`を呼ぶときは`gcloud.cmd`を使う

素の`gcloud`（拡張子なしのシェルスクリプト）をこのマシンのBashツールから実行すると、
`Python`とだけ出力して終了コード49で失敗する。原因は、`gcloud`スクリプトが
Windows向けの同梱Python（`platform/bundledpythonunix/bin/python3`）を探しに行き
見つからないため、通常の`python`コマンドへフォールバックし、それがこのマシンで
Microsoft Storeのダミーpython（`python --version`が失敗する。[開発環境.md](開発環境.md)参照）
に行き着くこと。

**対処**: フルパスで`gcloud.cmd`を呼ぶ。

```bash
"/c/Users/user/AppData/Local/Google/Cloud SDK/google-cloud-sdk/bin/gcloud.cmd" config list
```

## 2026-09-06 PowerShellでカンマ区切りの引数は必ずダブルクォートで囲む

`gcloud run deploy` / `services update`の`--set-secrets` `--update-secrets`のように
カンマ区切りの値を渡すオプションを、PowerShellで引用符なしで実行すると、カンマが
バラバラの引数として解釈され、gcloudが`Invalid secret spec`でクラッシュする。

```powershell
# NG: カンマで分割されて壊れる
--set-secrets=A=a:latest,B=b:latest

# OK: 値全体をダブルクォートで囲む
--set-secrets="A=a:latest,B=b:latest"
```

## 2026-09-06 Artifact Registryの`--description`に日本語を入れるとパス解釈が壊れる

`gcloud artifacts repositories create`に日本語を含む`--description="..."`を付けて
実行すると、`gcloud.cmd`自体のパス（`C:\Users\user\...\Cloud SDK\...`）が空白の位置で
分割されてしまい、`'C:\Users\user\AppData\Local\Google\Cloud' は、内部コマンドまたは
外部コマンド...として認識されていません。`という文字化けしたエラーになる。原因未特定。

**対処**: `--description`を付けずに作成する（必須項目ではない）。どうしても説明を
残したい場合は英数字のみにする。
