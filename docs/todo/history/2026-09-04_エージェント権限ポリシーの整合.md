## 見つかったずれ

テンプレートから引き継いだ状態で、正本と写しが 7 点ずれていた。

| 内容 | 影響 |
| --- | --- |
| `.vscode/settings.json` の正規表現がすべて 1 つの `\` で書かれていた | JSON として読めない。`\w` `\s` `\.` は不正なエスケープ、`\b` はバックスペース文字になる。**Copilot の許可・禁止ルールが丸ごと効いていなかった** |
| `.claude/settings.json` の `.env` 禁止が `Read(.env)` だけだった | `cat .env` で読める。`.env.local` も対象外 |
| `.claude/settings.json` の強制 push 禁止が `--force` だけだった | `-f` と `--force-with-lease` が素通り |
| `.claude/settings.json` の `prisma migrate reset` 禁止が素の呼び出しだけだった | `pnpm prisma migrate reset` / `npx prisma migrate reset` が素通り |
| `.codex/rules/project.rules` に `pnpm test:*` が無かった | `pnpm test:e2e` が毎回確認になる（安全側なので実害は小さい） |
| `.claude/settings.json` の `git branch` だけ引数なしの完全一致だった | `git branch -a` が毎回確認になる |
| `.claude/settings.json` にだけ「将来追加する行」のコメント雛形が無い | JSON はコメントを書けないため。仕組み上どうにもならない |

**なぜ気付けなかったか**: 4 ファイルを手作業で同期しており、正しく写せたかを確かめる手段が無かった。とくに Copilot 側は「ルールが効いていない」状態が無言で成立する（エラーにならず、ただ毎回確認が出るだけ）。

## 決めたこと

- **判定を 2 段階から 3 段階へ広げた。** 「許可 / 禁止」だけでは、`pnpm add` や `git push` のような「やってよいが黙ってやられると困る」操作の置き場所が無く、結果として表から漏れていた。Claude Code の `ask`・Codex の `prompt` に対応する「確認」を正本に足した。
- **`git add` / `git commit` / `git checkout -b` / `git switch -c` を許可側へ移した。** 手元に閉じてやり直せるため。リモートへ出る `git push` は「確認」に残した。
- **`pnpm exec` / `pnpm dlx` / `npx` は「確認」に置いた。** 前方一致で判定する仕組みでは、これらを挟まれると禁止コマンドをすり抜けられる。すべての組み合わせを並べるより、入口そのものを確認扱いにするほうが確実。
- **`supabase db reset` と `gcloud run deploy` / `gcloud run services delete` を禁止に足した。** 前者は `pnpm db:reset` と同じ破壊力、後者は本番の差し替え・削除にあたる。Supabase と Cloud Run を採用しているのに、どの表にも載っていなかった。
- **ローカル DB を Docker で動かす雛形は消した。** DB は Supabase を使う前提で、`docker/` も存在しないため。
- **3 ツールぶんの設定は残す。** いま使っているのは Claude Code だけだが、スキルとサブエージェントの入口が 3 ツールぶん揃っている中で権限だけ外すと方針が割れる。代わりに、ずれを機械的に検出する仕組みを足した。

## 残した限界

前方一致で判定する仕組みの穴は、今回の変更では埋まらない。

- `git push origin main --force` のようにフラグが後ろに回った形は一致しない。
- Windows で `pwsh -Command "<コマンド>"` の形に包まれるとトークン列が一致しない。
- `.env` の読み取り禁止は、シェル経由（`cat .env` 等）しか押さえられない。エージェント組み込みのファイル読み取りツールには効かない（Claude Code だけは `Read(.env)` で押さえられる）。

いずれも `docs/agent_permissions.md` の「注意点」に書いてある。**強制の穴がある以上、禁止リストは規約として守る前提を崩さない。**
