## 2026-09-07 GitHub ActionsからCloud RunへのWorkload Identity連携によるCI/CDを設定した（タスク10）

方針は[`infra_design_06_今後の課題.md`](../../specs/99_infra/infra_design_06_今後の課題.md)の1節どおり。手順を[`infra_design_07_CI_CDの自動化.md`](../../specs/99_infra/infra_design_07_CI_CDの自動化.md)として新規に書き、その手順に沿ってGCP側の準備と`.github/workflows/ci.yml`への`deploy-api`/`deploy-web`ジョブ追加を行った。

- GCP側（Workload Identity連携）はエージェントが`gcloud`で実施した。実際に作った値:
  - サービスアカウント: `github-actions-deployer@food-stock-manager-507709.iam.gserviceaccount.com`（`roles/artifactregistry.writer` `roles/run.developer`をプロジェクトに、`roles/iam.serviceAccountUser`を既定のCompute Engineサービスアカウント`450943687130-compute@developer.gserviceaccount.com`に付与）
  - Workload Identityプール: `github-actions-pool`（`global`）、プロバイダ: `github-actions-provider`（issuer `https://token.actions.githubusercontent.com`）。`--attribute-condition`で`assertion.repository == 'koekoebaborak27/food-stock-manager'`に絞り、他リポジトリから借用できないようにした。
  - プロバイダのフルパス: `projects/450943687130/locations/global/workloadIdentityPools/github-actions-pool/providers/github-actions-provider`
- `gcloud iam service-accounts create ... --display-name="GitHub Actions Deployer"`で、表示名にスペースを含めたところ[`インフラ構築.md`](../notes/インフラ構築.md#2026-09-07-引数にスペースを含むgcloudcmd呼び出しは--flags-fileで回避する)と同じ文字化けエラーが再発した。「フルパスをダブルクォートで囲む」対処では直らず、`--flags-file`でのみ解決した。今後はスペースを含む引数は例外なく`--flags-file`を使う方針に統一し、[`インフラ構築.md`](../notes/インフラ構築.md)に追記した。
- GitHub Secrets（`WIF_PROVIDER` `WIF_SERVICE_ACCOUNT` `GCP_PROJECT_ID` `VAPID_PUBLIC_KEY`）はユーザーがGitHubの画面から登録した。`VAPID_PUBLIC_KEY`はSecret Managerの`vapid-public-key`（公開鍵のため機密ではない）から取得した値をそのまま使った。
- ワークフローは`verify`ジョブの後ろに`deploy-api`→`deploy-web`を追加し、`push`かつ`main`ブランチのときだけ動くようにした（`pull_request`では動かさない）。[04_Cloud_Run](../../specs/99_infra/infra_design_04_Cloud_Run.md)と同じ`--set-secrets`・`--min-instances=0`・`--max-instances=2`をそのまま使い、`deploy-web`は`deploy-api`が確認したapiのURLを`needs.deploy-api.outputs.api_url`で受け取ってビルド引数に渡す。
- このセッションではPR作成までを行い、マージ・実際のCI実行での動作確認は次回に持ち越す。マージ後、GitHubの「Actions」タブで`verify`→`deploy-api`→`deploy-web`が緑になることと、本番URLへの反映を確認すること。

## 2026-09-07 PR #32をマージし、実際のCI実行でCloud Runへの自動デプロイが動くことを確認した

[`gh pr merge 32 --squash --delete-branch`](https://github.com/koekoebaborak27/food-stock-manager/pull/32)でマージ。`main`へのpush（Actions run `34088207026`）で、`verify`（1分9秒）→`deploy-api`（2分39秒）→`deploy-web`（1分28秒）の順にすべて成功した。Workload Identity連携での認証・Artifact Registryへのpush・Cloud Runへのデプロイ・`deploy-api`から`deploy-web`へのAPI URL受け渡し（`needs.deploy-api.outputs.api_url`）が、いずれも設計どおり動くことを実際のCI実行で確認できた。

本番web URL（`https://web-450943687130.asia-northeast1.run.app`）に`curl`すると`307`（未ログイン時のリダイレクト。想定どおり）が返り、デプロイが反映されていることも確認した。タスク10はこれで完了。
