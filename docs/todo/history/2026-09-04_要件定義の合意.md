# 2026-09-04 要件定義の合意

「おうちde常備食」の要件を、一問一答で31件確認して確定した。決定内容の正本は [`docs/specs/01_requirements/`](../../specs/01_requirements/README.md)。ここには「なぜそう決めたか」と、選ばなかった案を残す。

## 決定一覧

| # | 論点 | 決定 | 補足 |
| --- | --- | --- | --- |
| 1 | 世帯への参加方法 | 招待コード方式 | 招待リンクは有効期限・使用回数制限・承認が必要になり見送り |
| 2 | 招待コードの有効期限 | 7日間 | 相手がアプリを入れるまでの猶予を優先。推奨は24時間だった |
| 3 | 複数世帯への所属 | 1世帯のみ | 世帯切替UIと全APIへの世帯指定を避ける |
| 4 | 初回ログイン後 | 「つくる／参加する」の2択画面を必ず挟む | 自動作成にすると、あとから家族に合流できなくなる |
| 5 | 機種変更への備え | 案内文＋全員が招待コードを発行可 | 引き継ぎコードは乗っ取りリスクがあり見送り。同じGoogleアカウントでのログインが基本 |
| 6 | 権限 | データ操作はフラット、除名と世帯削除のみ管理者 | 管理者は世帯作成者が自動就任。譲渡は将来 |
| 7 | 残数の形式 | 整数 0〜99 | 半端な残りは単位「食分」で表す |
| 8 | 残数0のとき | 確認シートで「使い切り／買い物リストへ追加／そのまま」 | 自動削除は押し間違いで消える体験が悪い |
| 9 | 期限の種類 | 賞味期限と消費期限を区別しない | 種別カラムも持たない。将来の出し分けは断念 |
| 10 | 期限の入力 | 日付のみ・カレンダーだけ | クイックボタンは将来拡張 |
| 11 | 期限なし食品 | 期限は任意入力 | 米・塩に期限を強制すると登録されなくなる |
| 12 | 期限の色分け | 4段階（期限切れ／今日・明日／3日以内／通常） | 色・文言・アイコンの3重表現。5段階は暖色パレットで色差が取れない |
| 13 | 使い切り・削除データ | 論理削除し、履歴画面もMVPで作る | 推奨は履歴画面を後回しだったが、MVPに入れる判断 |
| 14 | 履歴の中身 | 使い切りのみ＋再登録導線 | 削除は履歴に載せない。誤削除は直後の取り消しで救う |
| 15 | 一覧の既定の並び順 | 期限が近い順 | 食べ忘れを減らすという目的に直結 |
| 16 | 一覧上部の構成 | 2段に圧縮（保存区分タブ＋期限注意バー） | 「家族de TODO」はフィルタ4段でカードが画面半分下から始まっていた |
| 17 | 購入済み→常備食 | 確認のうえ残数1・期限なしで登録。あとから更新 | 理由：レジや買い物中はできるだけ画面操作をしたくない |
| 18 | 確認のタイミング | 1件ごとに確認 | まとめて確認する案も提示したが、品目ごとに戻す／戻さないを選べる方を採用 |
| 19 | 直接追加品の保存区分 | 確認メッセージ内で3ピルから選ぶ | 冷蔵を初期値に自動設定する案より、データの正しさを優先 |
| 20 | 家族への反映 | 再読込ベース | Cloud Run は最小インスタンス0が前提のため常時接続は重い |
| 21 | 更新の競合 | 更新日時で検出して知らせる | 残数の増減だけは差分として扱い、同時操作でも正しく減る |
| 22 | オフライン | 対応しない | いったん「編集もオフライン可」を選んだが、実装量を踏まえて撤回 |
| 23 | オフライン範囲 | （22で撤回） | 「インターネットへの接続が必要です」と表示する |
| 24 | プッシュ通知 | MVPに入れる | 推奨は見送りだったが、入れる判断 |
| 25 | 通知の内容 | 1日1回・まとめて1通 | 食品ごとの個別通知は数が多い日に切られる |
| 26 | 単位 | 選択式6種・任意（未選択可） | 自由入力は表記ゆれを生む。未選択のときは数字だけ表示 |
| 27 | 作り置きの区別 | ピル1つで区別（任意） | このアプリの独自性。保存区分タブには混ぜない |
| 28 | 写真 | MVPでは入れない | 保管先・アップロード・圧縮・削除の後始末が一つながりで必要になる |
| 29 | 同名の登録 | 許可し、警告だけ出す | 期限違いの同名食品は別物として管理したい |
| 30 | 脱退・退会時 | 食品は残し、名前を匿名化 | 食品は世帯の資産。個人情報だけ確実に消す |
| 31 | 下部ナビ | 常備食／買い物／履歴 の3タブ | 当初案の「追加」タブはFABと役割が重複するため差し替え |

## 提示したが採用されなかった主な推奨

- 招待コードの有効期限を24時間にする案（→7日を採用）。
- 期限入力のクイックボタン（+3日 / +1週間 / +1ヶ月）を置く案（→将来拡張へ）。
- 使い切り履歴の画面をMVPでは作らない案（→MVPで作る）。
- 常備食へ戻す確認を、帰宅後にまとめて1回出す案（→1件ごとの確認）。
- プッシュ通知をフェーズ2に回す案（→MVPに入れる）。
