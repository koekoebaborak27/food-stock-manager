# ローカル環境での実行手順

このプロジェクトを手元のPCで動かすための手順。初めて動かすときの準備と、日々の起動・終了、詰まりやすいエラーの対処をまとめる。

## 前提

| 項目 | 内容 |
|---|---|
| Node.js | `.nvmrc` に書かれたバージョン（22系） |
| パッケージマネージャ | pnpm |
| DB | Docker（`docker/docker-compose.yml` でPostgresを起動）。**Googleログインを実際に試さず、画面の見た目だけ確認するなら不要** |
| Google OAuth | Google Cloud ConsoleでOAuthクライアントIDを発行したもの。**これも見た目確認だけなら不要** |

## 初回だけ行うこと

### 1. 依存パッケージを取得する

```bash
pnpm install
```

### 2. 環境変数ファイルを作る

```bash
cp .env.example .env
```

`.env.example` の説明を見ながら値を埋める。Googleログインを実際に試す場合は `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` が必要（[認証と家族グループの設計書](../specs/02_basic-design/10_認証と家族グループ/README.md)を参照）。画面の見た目だけ確認するなら空のままでよい。

### 3. ローカルDBを起動する（Googleログインを試す場合のみ）

```bash
docker compose -f docker/docker-compose.yml up -d db
```

### 4. マイグレーションを反映する（Googleログインを試す場合のみ）

```bash
pnpm prisma:migrate
```

## 日々の起動方法

ターミナルを2つ開いて、それぞれで実行する（同じターミナルで続けて実行すると、1つ目がフォアグラウンドで動き続けて2つ目が起動しない）。

```bash
pnpm dev:web
```

```bash
pnpm dev:api
```

| コマンド | 役割 | ポート |
|---|---|---|
| `pnpm dev:web` | 画面（Next.js） | 3000 |
| `pnpm dev:api` | API（NestJS） | 3001 |

起動後、ブラウザで http://localhost:3000 を開く。

**画面の見た目だけを確認したいとき**（Googleログインは押さない）は `pnpm dev:web` だけでよい。`pnpm dev:api` を起動していなくても画面は表示される。

## ログイン画面（`/login`）を見る方法

すでにログイン済み（ブラウザにセッションCookieが残っている）だと、`/login` を開いても自動的に `/` へ戻される（[ログイン状態に応じた振り分け](../../apps/web/src/proxy.ts)の仕様）。ログイン画面を見るには、次のどちらかを行う。

- 画面に出ている「ログアウト」を押してから `/login` を開く
- ブラウザのシークレットウィンドウ（Cookieを持たない状態）で `/login` を開く

## 終了方法

各ターミナルで `Ctrl+C`。

DBも止める場合（起動していれば）。

```bash
docker compose -f docker/docker-compose.yml down
```

**`down -v` はボリューム（DBの中身）ごと消すため、開発データを残したい場合は付けない。**

## よくあるエラー

### `Another next dev server is already running`

同じ `apps/web` ディレクトリで、すでに別の `next dev` が動いている。自分で起動したターミナルを閉じ忘れているほか、Claude Code のプレビュー機能（ブラウザ確認用に裏で起動するサーバー）が動いたままになっているときにも起こる。

エラーメッセージに表示される `PID` を見て、次のどちらかで解決する。

- そのまま使う: 表示された `http://localhost:3000` にアクセスすればよく、`pnpm dev:web` を再実行する必要はない
- 止めてから自分で起動し直す:

```bash
taskkill /PID <表示されたPID番号> /F
```

止めたあと、もう一度 `pnpm dev:web` を実行する。

### ポートがすでに使われている（3000 / 3001）

上記と同様に、別プロセスがポートを掴んでいないか確認する。

```bash
netstat -ano | findstr :3000
```

表示された行の右端がPID。そのPIDを `taskkill /PID <PID> /F` で止めてから、起動し直す。
