# データベース

列の共通ルール（`id` `createdAt` `updatedAt`、家族グループでの切り分け、作った人・更新した人、消し方、個人情報の消し方）は [01_データベース共通.md](../00_共通/01_データベース共通.md) のとおり。ここでは `ShoppingItem` の列を定める。

## 1. ShoppingItem

| 列 | 型 | 決まり |
| --- | --- | --- |
| `householdId` | UUID | 属する家族グループ。外部キー、索引あり |
| `name` | 文字列（30文字以内） | 商品名。必須。前後の空白を除いて保存する |
| `isPurchased` | 真偽値 | 購入済みなら `true`。既定値 `false` |
| `sourceStockId` | UUID、null許容 | 追加元の常備食。`Stock` への外部キー。直接入力では `null` |
| `createdById` | UUID、null許容 | 追加した利用者（[01_データベース共通.md 4](../00_共通/01_データベース共通.md#4-作った人更新した人)） |
| `updatedById` | UUID、null許容 | 最後に更新した利用者 |
| `deletedAt` | 日時、null許容 | 削除した日時（[01_データベース共通.md 6](../00_共通/01_データベース共通.md#6-消し方)） |

- 一覧の問い合わせは常に `householdId` と `deletedAt IS NULL` で絞る。未購入を先に `isPurchased` の昇順で並べ、その中では `createdAt` の昇順とする。購入済みも `createdAt` の昇順とする。
- 一覧と重複確認に使う索引は `(householdId, deletedAt, isPurchased, name)` に付ける。
- 同じ世帯の未購入の商品名を重複させないため、`householdId`・`name` の前後空白を除いた値・`isPurchased = false`・`deletedAt IS NULL` の組み合わせに一意制約を付ける。購入済みと削除済みの商品はこの制約に含めない。
- `sourceStockId` が指す `Stock` を削除しても、買い物リストの商品は削除しない。元の食品が使えなくなったことは、購入済みにする時点で判定する。
- 一意制約は、保存済みの `(householdId, name)` に対し `isPurchased = false AND deletedAt IS NULL` を条件とする部分一意索引で実現する。追加・未購入への変更・復元のすべてに適用する。
- 並び順の同順位は `id` の昇順で決める。商品名の重複比較は大文字・小文字などを同一視しない設定とする。
- `sourceStockId` は同じ世帯の食品だけを参照させ、書き込み時と購入処理時に確認する。元の食品を物理削除するときは `null` にし、商品を連動削除しない。
- 新規作成した常備食の ID で `sourceStockId` を書き換えない。この列は追加元を記録するものであり、購入結果は保持しない。
