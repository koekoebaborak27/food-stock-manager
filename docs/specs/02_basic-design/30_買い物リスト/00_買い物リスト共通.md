# 買い物リスト共通

## 1. 権限

世帯に所属する利用者は全員、商品を追加・購入済みに変更・未購入へ戻す・削除できる。追加者や元の常備食の登録者が別の利用者でも、操作を制限しない。

## 2. 商品の追加と重複

商品の追加元は次の 2 種類とする。

| 追加元 | 受け取る値 | 保存する値 |
| --- | --- | --- |
| 常備食 | `Stock` の ID | サーバーで食品名を商品名へ写し、`sourceStockId` に ID を保存する |
| 直接入力 | 商品名 | 前後の空白を除いた商品名を保存し、`sourceStockId` は `null` とする |

- 常備食から追加できるのは、同じ世帯に属し、削除されていない `Stock` だけとする。消費済の `Stock` は追加できる。
- 直接入力の商品名は 1〜30 文字とする。空白だけの入力は未入力として扱う。
- 同じ世帯に、削除されておらず未購入の同名商品があれば、追加しない。比較には前後の空白を除いた商品名を使い、大文字・小文字は区別する。
- 購入済みの商品は重複の判定対象にしない。同名の商品を新しく未購入として追加できる。
- 重複を検出してから作成するまでを 1 つの処理として行う。2 人が同時に同じ商品を追加しても、未購入の商品を 2 件作らない。
- 購入済みから未購入へ戻すときと、削除した未購入商品を復元するときも同じ重複判定を行う。同名の未購入商品があれば変更せず、`SHOPPING_ITEM_ALREADY_EXISTS` を返す。既存商品へまとめたり削除したりしない。
- 常備食の名称をあとから変更しても、追加済みの商品名は変更しない。全角・半角やひらがな・カタカナの変換は行わず、文字列が一致する場合だけ重複とする。
- 在庫切れシートの「消費済にして、買い物リストに追加する」は、[常備食の消費済 API](../20_常備食管理/02_API.md) から同じ追加処理を呼ぶ。同名の未購入商品がある場合は追加を省き、消費済への変更は完了する。それ以外の失敗では両方とも変更しない。

## 3. 購入状態と常備食への登録

未購入の商品を購入済みにするときだけ、画面は購入済みにするかに加え、常備食へ戻すかを確認する。購入済みから未購入へ戻すときは確認を出さず、常備食には何もしない。

常備食へ戻すことを選んだ場合は、購入状態の変更と次の処理を 1 つの処理として行う。片方だけ成功させない。

| `sourceStockId` の状態 | 常備食に対する処理 |
| --- | --- |
| 元の `Stock` があり、削除・消費済のどちらでもなく、選択した保存区分が同じ | その `Stock` の残数を 1 増やす |
| 元の `Stock` があり、選択した保存区分が異なる | 元の `Stock` は変更せず、選択した保存区分で新しい `Stock` を作る |
| 元の `Stock` がない、削除済、または消費済 | 商品名で新しい `Stock` を作る |
| `sourceStockId` がない | 商品名で新しい `Stock` を作る |

- 新しく作る `Stock` は、残数を 1、期限を `null`、単位を `null`、作り置きを `false`、メモを `null` とする。保存区分はシートで選んだ値を使う。
- 元の `Stock` が未削除なら、消費済の場合も含めてその保存区分をシートの初期値にする。元の食品がないか削除済みなら `REFRIGERATED`（冷蔵）を初期値にする。
- 常備食を作成・更新した利用者は、この購入操作をした利用者とする。
- 消費済かどうかは `consumedAt` で判断する。残数 0 でも未削除かつ `consumedAt` が `null` で保存区分が同じなら元の常備食へ加算する。新規作成では `consumedAt` と `deletedAt` を `null` にする。
- 同じ保存区分の元の常備食へ加算する場合だけ、残数が上限 99 なら商品・常備食をどちらも変更せず `SOURCE_STOCK_QUANTITY_LIMIT` を返す。シートで「常備食へ戻さない」を選べば購入済みにできる。別の保存区分で新規作成する場合は、元の残数が 99 でも登録できる。
- 購入処理では商品と元の常備食を同じ処理の中で更新対象として確保し、最新の削除・消費済・残数を判定する。同時購入や残数の増減による加算の取りこぼし、上限超過を防ぐ。
- 保存区分の比較にも処理時点の元食品の値を使う。シートを開いたあとに家族が元食品の保存区分を変更した場合も、利用者が選択して送った保存区分を優先し、異なれば新規作成する。加算時は元食品の残数と更新者・更新日時だけを変更し、新規作成時は同名の別食品へ合算しない。
- 商品の `updatedAt` を照合し、すでに購入済みの商品を再度購入済みにする要求は競合とする。通信の再送で常備食を重ねて増やさない。未購入に戻したあとで再び購入する操作は、新しい購入として扱う。未購入への変更では前回登録した常備食を減らさない。

## 4. 削除と元に戻す

- 1 件削除と購入済みの一括削除は、どちらも `deletedAt` を設定する論理削除とする（[01_データベース共通.md 6](../00_共通/01_データベース共通.md#6-消し方)）。常備食は変更しない。
- 削除後は画面下部の帯に「元に戻す」を 5 秒出す。一括削除では、同じ操作で削除した商品をまとめて戻す。
- 元に戻すときは `deletedAt` を `null` に戻し、購入状態と商品名は削除前のままにする。
- 一括削除は確認画面に表示した購入済み商品の ID と `updatedAt` を対象とする。確認後に購入された別の商品は含めない。対象の一部でも更新・削除済みなら、全件を変更せず競合を返す。
- 復元には削除成功時に返した ID と削除後の `updatedAt` を使う。すべて同じ世帯の削除済み商品で、日時が一致する場合だけまとめて復元する。1 件でも対象外・競合・重複があれば全件を変更しない。5 秒の受付表示は共通の画面仕様に従う。
