# 画面共通

すべての画面に共通する構造と表示の決まり。画面ごとの表示項目・入力チェックは各機能の設計書に書く。

## 1. 画面の枠

ログイン後のすべての画面を、次の 3 段構成にすること。

| 位置 | 中身 |
| --- | --- |
| 上段（ヘッダー） | 画面の見出し。右端にメニューボタン（横三本線）。子画面では左端に戻るボタン |
| 中段 | その画面の内容。縦にだけスクロールさせること |
| 下段（下部タブ） | 「常備食」「買い物」「消費済」の 3 つ |

- 下部タブは常備食リスト・買い物リスト・消費済リストの 3 画面にだけ出すこと。子画面には出さないこと。
- ヘッダーのメニューから開く画面は「メンバーと家族グループ」「通知の設定」「アカウントの設定」の 3 つとすること。メニューは 3 つのタブすべてのヘッダーに置くこと。
- ログイン画面と家族グループの選択・作成・参加の画面には、ヘッダーのメニューと下段のタブを出さないこと。
- 中段は、下段のタブと右下の追加ボタンに隠れる分だけ下に余白を取ること。一番下の項目が押せなくならないようにすること。

## 2. 右下の追加ボタン（FAB）

- 常備食リストと買い物リストにだけ置くこと。消費済リストには置かないこと。
- 下部タブに重ならない位置に置くこと。
- アイコンはプラス 1 つとし、文字を添えないこと。押したときに何が開くかは画面ごとの設計書に書く。

## 3. タグの表示

食品と商品に付ける短いラベルは、すべて角丸のピル型で表すこと。文字だけで意味が分かるようにし、色を意味の唯一の手がかりにしないこと。

### 3.1 保存区分

| 保存区分 | 表示する文字 | アイコン |
| --- | --- | --- |
| 冷蔵 | 冷蔵 | 冷蔵庫の線画 |
| 冷凍 | 冷凍 | 雪の結晶の線画 |
| 常温 | 常温 | 戸棚の線画 |

- 色は `secondary` を使い、3 区分で色を変えないこと。区別は文字とアイコンで付けること。

### 3.2 期限の状態

期限の状態は、その日の日本時間の日付と期限の日付の差で決めること。時刻は使わないこと。

| 状態 | 条件（期限 − 今日） | 表示する文字 | アイコン | 色トークン |
| --- | --- | --- | --- | --- |
| 期限切れ | −1 日以下 | 期限切れ（N日前） | 丸で囲んだ感嘆符 | `destructive` |
| 今日 | 0 日 | 今日まで | 時計 | `primary` |
| 明日 | +1 日 | 明日まで | 時計 | `primary` |
| もうすぐ | +2 日 / +3 日 | あとN日 | 砂時計 | `accent` |
| 通常 | +4 日以上 | M/Dまで | カレンダー | `muted` |
| 表示なし | 期限が未設定 | （タグを出さないこと） | — | — |

- N には日数の絶対値を入れること。例: 3 日前に切れていれば「期限切れ（3日前）」、2 日後なら「あと2日」。
- 「M/Dまで」の M と D に 0 を付けないこと。例: 「9/5まで」。
- 期限切れの食品を自動で消さないこと。一覧から隠さないこと。

### 3.3 作り置き

- 作り置きの食品にだけ「作り置き」のタグを鍋の線画とともに出すこと。作り置きでない食品に「購入品」等のタグを出さないこと。

## 4. 数と日付の書き方

| 対象 | 書き方 | 例 |
| --- | --- | --- |
| 残数（単位あり） | 数字 + 単位 | 3個 |
| 残数（単位なし） | 数字だけ | 3 |
| 期限（一覧・タグ） | M/D | 9/5 |
| 期限（詳細・確認文） | YYYY年M月D日 | 2026年9月5日 |
| 日時（詳細） | YYYY年M月D日 H:MM | 2026年9月5日 8:30 |

- 画面に出す日付と日時は、すべて日本時間へ直してから表示すること。
- 「今日」「明日」の判定も日本時間で行うこと。日付が変わる境目は日本時間の 0 時とすること。

## 5. 人の名前の表示

- 作成者・更新者・メンバーの一覧には、Google アカウントの表示名を出すこと。
- 家族グループから抜けた人・退会した人は「退会したメンバー」と出すこと。アイコンは出さず、灰色の丸に人型の線画を出すこと。
- メールアドレスを一覧に出さないこと。出すのはアカウントの設定画面で本人のものだけとすること。

## 6. 操作したことの伝え方

### 6.1 画面下部の短い帯

画面を移さない操作の結果は、画面下部に短い帯を出して伝えること。

- 下部タブのすぐ上に重ねて出し、タブを隠さないこと。
- 表示は 3 秒で消えること。「元に戻す」を付ける場合だけ 5 秒とすること。
- 同時に 2 つ以上出さないこと。次の帯を出すときは前の帯を消すこと。
- 帯に出す文字は [03_共通文言.md](03_共通文言.md) の一覧から選ぶこと。

### 6.2 確認ダイアログ

取り消せない操作の前には確認ダイアログを出すこと。対象は削除・除名・家族グループの削除・脱退・退会とすること。

- ボタンは左に「キャンセル」、右に実行のボタンを置くこと。
- 実行のボタンだけを `destructive` の色にすること。ダイアログを開く前のアイコン（ゴミ箱など）を赤で塗らないこと。
- ダイアログの外側を押したときは、何もせずに閉じること。
- 見出しと本文の文字は [03_共通文言.md](03_共通文言.md) に書いたものを使うこと。

### 6.3 下から出るシート

選択肢が 3 つ以上ある分岐は、画面を移さず下から出るシートで選ばせること。残数が 0 になったときと、買い物リストで購入済みにしたときがこれにあたる（[画面遷移図 図02](../画面遷移図.md)）。

- シートには見出しと選択肢を縦に並べ、一番下に「キャンセル」を置くこと。
- 選択肢を 4 つより多くしないこと。

## 7. 読み込み中・空・失敗の表示

一覧を出す画面は、次の 4 つの状態を必ず持つこと。

| 状態 | 出すもの |
| --- | --- |
| 読み込み中 | カードの形をした灰色の枠を 3 つ出すこと。回転する印だけにしないこと |
| 中身あり | 一覧 |
| 0 件 | 中央に短い説明と、次にする操作のボタンを 1 つ出すこと。文言は各機能の設計書に書く |
| 失敗 | 中央にエラーの文言と「もう一度読み込む」のボタンを出すこと |

- 引き下げて再読込できるようにすること。再読込の最中も、前に読み込んだ内容を表示したままにすること。
- 一覧を開いたときと引き下げたときにだけ読み込むこと。開いたまま自動で読み直し続けないこと。

## 8. 入力チェックの出し方

- 保存や追加のボタンを押した時点で、すべての項目をまとめて調べること。入力中の 1 文字ごとに赤くしないこと。
- 一度エラーを出した項目は、その後は入力を変えるたびに調べ直すこと。直した時点でエラーの表示を消すこと。
- エラーの文言は、その項目の入力欄のすぐ下に赤い文字で出すこと。まとめて画面上部に出さないこと。
- エラーがある状態で保存を押したときは、一番上のエラー項目まで画面をスクロールさせること。
- 保存のボタンは、押せない見た目にしないこと。押させたうえでエラーを見せること。
- 保存中はボタンを押せなくし、二重に登録されないようにすること。

## 9. 権限による表示の差

- 一般メンバーにできない操作（他のメンバーの除名、家族グループの削除）は、ボタン自体を出さないこと。押せない見た目で出さないこと。
- 画面に出していない操作でも、バックエンド側で必ず権限を確かめること（[02_API共通.md](02_API共通.md)）。

## 10. 通信できないとき

- 通信できない状態を検知したら、画面上部に「インターネットへの接続が必要です」の帯を出し、消えないようにすること。
- その間は登録・編集・削除・残数の増減のボタンを押せなくすること。表示済みの内容は消さないこと。
- 通信が戻ったら帯を消し、表示中の一覧を読み直すこと。
