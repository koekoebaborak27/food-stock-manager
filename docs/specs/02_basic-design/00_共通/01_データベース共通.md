# データベース共通

テーブルの全体像と、すべてのテーブルに共通する決まりを書く。列の詳しい定義は、そのテーブルを主に使う機能の設計書に書くこと。

## 1. テーブルの一覧

| テーブル | 何を持つか | 定義を書く場所 |
| --- | --- | --- |
| `User` | ログインした利用者。Google アカウントの表示名・メールアドレス・アイコンURL | 10_認証と家族グループ |
| `Household` | 家族グループ。名前と管理者 | 10_認証と家族グループ |
| `Membership` | 誰がどの家族グループに属しているか | 10_認証と家族グループ |
| `Invitation` | 招待コードと有効期限 | 10_認証と家族グループ |
| `Stock` | 常備食。食品名・保存区分・残数・単位・期限・作り置き・メモ | 20_常備食管理 |
| `ShoppingItem` | 買い物リストの商品。商品名・購入したかどうか | 30_買い物リスト |
| `PushSubscription` | 通知を送る先の端末 | 40_期限通知 |
| `NotificationSetting` | 家族グループごとの通知時刻 | 40_期限通知 |

- テーブルを増やすときは、この表にも 1 行足すこと。
- 名前は Prisma のモデル定義をそのまま物理名にすること。テーブル名は英語の単数形の先頭大文字、列名は先頭小文字とすること（`prisma/AGENTS.md`）。

## 2. すべてのテーブルに共通する列

| 列 | 型 | 決まり |
| --- | --- | --- |
| `id` | UUID | 主キー。連番にしないこと。画面や経路に出しても他の行を推測できないようにするため |
| `createdAt` | 日時 | 行を作った日時。登録時に自動で入れること |
| `updatedAt` | 日時 | 最後に更新した日時。更新のたびに自動で入れること |

- 日時はすべて協定世界時（UTC）で保存すること。日本時間へ直すのは画面に出す直前だけとすること。
- 期限のように日付だけを持つ列は、時刻を持たない日付型にすること。時刻付きで保存しないこと。

## 3. 家族グループでの切り分け

- 家族グループに属するデータを持つテーブルには、必ず `householdId` の列を持たせること。対象は `Membership` `Invitation` `Stock` `ShoppingItem` `NotificationSetting`。
- `householdId` には家族グループへの外部キーを張り、索引（インデックス）を付けること。一覧の取得が必ずこの列で絞り込まれるため。
- 一覧を引く問い合わせには、必ず `householdId` の条件を付けること。付け忘れを防ぐため、条件を足す処理は共通のデータ取得層 1 か所にまとめること（[02_API共通.md](02_API共通.md)）。
- 家族グループの外にあるテーブルは `User` だけとすること。

## 4. 作った人・更新した人

`Stock` と `ShoppingItem` は、誰が作り誰が最後に更新したかを持つこと。

| 列 | 決まり |
| --- | --- |
| `createdById` | 登録した利用者。利用者が消えたときは空にすること |
| `updatedById` | 最後に更新した利用者。利用者が消えたときは空にすること |

- 空になった場合、画面には「退会したメンバー」と出すこと（[00_画面共通.md](00_画面共通.md)）。
- 利用者が消えても食品と商品の行は消さないこと。家族グループのものとして残すこと。

## 5. 更新の競合

2 人が同時に同じ食品を編集したとき、後から保存した内容で前の内容を消さないようにすること。

- 編集画面を開いたときに読んだ `updatedAt` を、保存のときに一緒に送らせること。
- 保存の直前に、データベース側の `updatedAt` と送られてきた値が同じかを確かめること。違う場合は保存せず、競合として返すこと。
- 残数の増減はこの確認の対象にしないこと。「1 増やす」「1 減らす」という差分としてデータベース側で足し引きすること。2 人が同時に 1 ずつ減らしたときは 2 減ること。
- 差分で減らした結果が 0 未満になる場合は 0 で止めること。マイナスの残数を保存しないこと。

## 6. 消し方

消し方は 3 種類ある。混同しないこと。

| 種類 | 対象 | やり方 |
| --- | --- | --- |
| 消費済にする | `Stock` | 行を残し、残数を 0 にすること。消費済リストに出すこと |
| 取り消す（削除） | `Stock` `ShoppingItem` | 行を残し、削除した印（`deletedAt` に日時）を付けること。一覧にも消費済リストにも出さないこと |
| 完全に消す | `Invitation` `PushSubscription` | 行そのものを消すこと |

- `deletedAt` に値が入っている行を、一覧の問い合わせで返さないこと。この条件も共通のデータ取得層で付けること。
- 削除の直後だけ「元に戻す」を受け付けること。戻すときは `deletedAt` を空に戻すこと。取り消せる時間は画面側で 5 秒とすること（[00_画面共通.md](00_画面共通.md)）。

## 7. 個人情報の消し方

家族グループから抜けたとき・退会したときは、その利用者の個人情報だけを消し、食品と商品は残すこと。

| 対象 | やること |
| --- | --- |
| `User` の表示名・メールアドレス・アイコンURL | 空にすること |
| `Membership` | その利用者の行を消すこと |
| `PushSubscription` | その利用者の行を消すこと |
| `Stock` `ShoppingItem` の `createdById` `updatedById` | その利用者を指していれば空にすること |
| `Stock` `ShoppingItem` の本体 | 消さないこと |

- 削除済み・消費済の行にも個人情報を残さないこと。上の処理は削除済みの行にも同じように行うこと。
- 家族グループそのものを削除するときは、その家族グループに属する行をすべて消すこと。`User` は消さないこと。
