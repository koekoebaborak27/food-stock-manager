# API

経路・応答の形・状態コードの決まりは [02_API共通.md](../00_共通/02_API共通.md) のとおり。ここでは経路の一覧と、この機能だけの `code`、内部配信 API の認証方法を定める。

## 1. 経路の一覧

| やること | 方法 | 経路 | 補足 |
| --- | --- | --- | --- |
| 通知時刻を取る | GET | `/api/notification-settings` | 行がなければ `{ "hour": 8, "minute": 0 }` を返す |
| 通知時刻を変える | PATCH | `/api/notification-settings` | 本文 `{ "hour": 8, "minute": 0 }`。`minute` は `0` `15` `30` `45` のみ。行がなければ作る |
| 自分の端末が購読済みか取る | GET | `/api/push-subscriptions/me` | `{ "subscribed": boolean }` |
| 購読を登録する | POST | `/api/push-subscriptions` | 本文 `{ "endpoint": "...", "keys": { "p256dh": "...", "auth": "..." } }`。すでに購読があれば置き換える |
| 購読を解除する | DELETE | `/api/push-subscriptions/me` | 購読がなくても 204 を返す（べき等） |
| 通知を配信する（内部専用） | POST | `/api/internal/notifications/dispatch` | Cloud Scheduler が 15 分ごとに呼ぶ。画面からは呼ばない |

- 通知時刻はログインしている利用者が属する世帯のものを扱う。[02_API共通.md 4](../00_共通/02_API共通.md#4-家族グループでの絞り込み)のとおり、世帯 ID はセッションから決める。

## 2. この機能だけの `code`

| 状態コード | `code` | どんなとき |
| --- | --- | --- |
| 400 | `NOTIFICATION_TIME_INVALID` | `minute` が `0` `15` `30` `45` 以外、または `hour` が範囲外 |
| 401 | `INTERNAL_UNAUTHORIZED` | 内部配信 API の認証情報が一致しない |

## 3. 内部配信 API の認証

`POST /api/internal/notifications/dispatch` は Cloud Scheduler からの呼び出し専用で、ログインしている利用者が呼ぶ経路ではない。[02_API共通.md 3](../00_共通/02_API共通.md#3-本人の特定)のセッションによる認証は使わず、次のとおりとする。

- 呼び出し元は、決められたヘッダー（例: `X-Internal-Secret`）に共有の合言葉を付けて呼ぶこと。
- バックエンドはヘッダーの値が、あらかじめ持っている値と一致するかだけを確かめること。一致しなければ 401 と `INTERNAL_UNAUTHORIZED` を返すこと。
- 合言葉の実際の値と受け渡し方法（環境変数名、Cloud Scheduler 側の設定）は、インフラ構築時に [`docs/specs/99_infra/`](../../99_infra/README.md) へ書くこと。
- この経路は Cookie を発行・確認しないこと。世帯の絞り込みも行わず、すべての世帯を対象に処理すること。

## 4. 配信処理の流れ

1. 現在の日本時間を 15 分単位の枠（0 分・15 分・30 分・45 分）に丸める。
2. `notifyHour` `notifyMinute` がその枠と一致し、`lastNotifiedOn` が今日でない世帯を、[01_データベース.md 2](01_データベース.md#2-notificationsetting)の条件付き更新で確保する。
3. 確保できた世帯ごとに、期限切れ・今日が期限・明日が期限の `Stock`（[00_画面共通.md 3.2](../00_共通/00_画面共通.md#32-期限の状態)の「期限切れ」「今日」「明日」に当たるもの）の件数を数える。
4. 件数が 0 件の世帯には配信しない。
5. 件数が 1 件以上の世帯は、その世帯に属し通知を有効にしている（`PushSubscription` を持つ）利用者全員に、次の内容で 1 通ずつ Web Push を送る。

   | 項目 | 内容 |
   | --- | --- |
   | 通知の見出し | 期限が近い食品があります |
   | 通知の本文 | 期限切れ・期限間近の食品が○件あります。 |
   | 押したときの遷移先 | 常備食リスト（[20_常備食管理/02_API.md](../20_常備食管理/02_API.md#1-経路の一覧)の `urgentOnly=true` に絞り込んだ状態。[画面遷移図 3 節](../画面遷移図.md#3-図01-全体の画面遷移)のとおり） |

- ○には手順 3 で数えた件数を入れる。
- 配信に失敗した購読（送信先が無効だった場合を含む）は再送しない。[01_データベース.md 1](01_データベース.md#1-pushsubscription)のとおり、無効な購読情報はこの処理の中で削除する。
