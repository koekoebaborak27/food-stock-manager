# データベース

列の共通ルール（`id` `createdAt` `updatedAt`、家族グループでの切り分け、消し方、個人情報の消し方）は [01_データベース共通.md](../00_共通/01_データベース共通.md) のとおり。ここでは、この機能が使う4つのテーブルの列を定める。

## 1. User

| 列 | 型 | 決まり |
| --- | --- | --- |
| `googleId` | 文字列 | Googleアカウントの識別子。一意。ログイン時にこの列で利用者を探す |
| `displayName` | 文字列、null許容 | 表示名。ログインのたびにGoogleアカウントの値で上書きする。脱退・退会で空にする |
| `email` | 文字列、null許容 | メールアドレス。扱いは`displayName`と同じ |
| `avatarUrl` | 文字列、null許容 | アイコンのURL。扱いは`displayName`と同じ |

- `User`の行は退会しても消さない。個人情報だけを空にする（[01_データベース共通.md 7](../00_共通/01_データベース共通.md#7-個人情報の消し方)）。同じGoogleアカウントで再びログインした場合は、その空になった行を見つけて`displayName``email``avatarUrl`を入れ直し、通常のログインとして扱う（新規登録の扱いにはしない）。

## 2. Household

| 列 | 型 | 決まり |
| --- | --- | --- |
| `name` | 文字列 | 家族グループの名前 |

- 管理者は列を持たない。`Membership.role`で判定する（1名だけが`ADMIN`になる）。
- 家族グループを削除するときは、`Household`の行と、それに紐づく`Membership``Invitation``Stock``ShoppingItem``NotificationSetting``PushSubscription`をすべて完全に消す（`User`は消さない）。

## 3. Membership

| 列 | 型 | 決まり |
| --- | --- | --- |
| `userId` | UUID | `User`への外部キー。一意（1人が同時に所属できる家族グループは1つ） |
| `householdId` | UUID | `Household`への外部キー |
| `role` | 列挙型（`ADMIN` \| `MEMBER`） | 家族グループにつき`ADMIN`は1人だけ |

## 4. Invitation

| 列 | 型 | 決まり |
| --- | --- | --- |
| `householdId` | UUID | `Household`への外部キー |
| `createdById` | UUID | 発行した`User`への外部キー。一意（1人が同時に持てる有効なコードは1つ） |
| `code` | 文字列 | 招待コード。一意 |
| `expiresAt` | 日時 | 発行から7日後 |

- 招待コードで参加が成功したときに、その`Invitation`の行を完全に消す（使い回し防止）。
- 期限切れのコードを再発行する場合は、古い行を完全に消してから新しい行を作る。
- 発行した利用者が脱退・退会・除名された場合、その`Invitation`の行も完全に消す。
